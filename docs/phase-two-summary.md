# 第二期：网络总览、菜单面板二级信息与概览

按 HTML 第二期原定范围实施。用户补发的双列菜单面板参考图单独保存，本期发布后先评估，不直接实施。

## 行为与读数

- 网络诊断首屏为总览：网络接口、代理/VPN、系统 DNS、外网 IP，公网延迟、上下行速率，24 小时/30 天总量与应用排行。保留诊断/测速/流量标签；检测详情和原 DNS 修改/恢复操作移到明确的详情入口。
- 外网 IP 与诊断仍由点击触发。公网延迟取 223.5.5.5 的 ICMP，路由器取网关 ICMP，DNS 取百度域名解析耗时；未测、失败或不可读均不能变成 0。
- 总览网卡总量和应用排行使用相同小时桶，避免覆盖不一致造成总量小于排行。窗口标注滚动 24 小时/30 天、小时记录和当前时段未结束，不伪称今天/本月。
- 上下行沿用 AppTraffic 的查看者计数和已有 2 秒采样；离开总览释放查看者。历史、物理网卡与应用数据均沿用既有采样器，没有新增采样计时器。
- 菜单面板每行增加温度、负载、交换空间、上下行、风扇和电池状态等二级读数；曲线到行尾，进程 CPU 沿用 30/80 阈值色。风扇主值为最快风扇，未提供读数显示未知，不添加调速写入。
- 概览用 KPIStrip 代替三张旧指标卡；原体检结论、处理入口与问题清单保留。

## 验收基础设施

SwiftUI 的 AX 树偶发需要外部客户端查询才生成。测试包新增仅供自检的子进程入口，只读查询它的父进程，使用相同签名与既有授权；不申请新权限，不读取其他应用内容。父进程泵送事件、有界等待，之后仍检查真实窗口和控件。它替代发生锁等待的同进程后台 AX 自查询，不绕过断言。

measure.sh 新增只读窗口探针，15 秒预热后记录真实 CPU 时间及 RSS 均值/峰值/结束值；采样期逐段确认面板是否可见。已有 App 实例或面板状态变化会使测量失败，避免双实例或面板提前关闭造成假结果。

## 性能与验收口径

开发阶段在 M1 Max / 64 GiB 真机上，预热 15 秒后测量 60 秒，并逐段确认面板可见。为了让用户继续操作电脑，两版均采用只增加测试参数的固定面板模式；2.6.2 基线所有 Swift 源文件与标签一致，只有一行弹出行为设置不同。

| 面板打开 | CPU 时间 / 实测时长 | CPU | RSS 采样均值 |
| --- | --- | --- | --- |
| 2.6.2 同条件基线 | 1.15 s / 60.10 s | 1.914% | 136.4 MiB |
| 第二期开发候选 | 1.12 s / 60.10 s | 1.864% | 140.8 MiB |

约 4 MiB 的 RSS 增量按用户明确确认接受，不能描述为内存零增加。这是开发候选的本机短时样本，最终发布包的逻辑、界面和签名另行验证。保留旧计时错误、面板中途关闭等无效记录，不将其计入结论。

进程行图标缓存限制为 16 pt / 2x 位图，并及时释放大图临时对象；复用已有字体，移除指标行重复悬停包装。数值与完整辅助功能文字保留。测量专用参数仅保持弹出面板并跳过升级修复，不新增采样器；普通启动仍使用日常行为。
