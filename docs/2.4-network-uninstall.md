# 2.4：按应用网络字节、流量历史、测速与卸载

2.3 的「按应用」一栏只是联网连接数，流量历史只在网络页打开时记录，测速只有整次平均值，Wi-Fi 读数依赖的 airport 工具在新系统上已不存在。本版把这些换成真实读数。

## 本轮实现

- 按应用流量：用系统自带的 `nettop` 按进程读取收发字节（只读，不需要管理员权限），两次读数相减得到真实字节；Helper 进程合并到所属 App。上次采样后才启动的进程，全部计数归入本段；起点不明的新进程和计数变小（pid 复用）的进程跳过，不估算。
- 入口：菜单栏面板的网络速率和「哪些应用在用网络」都会弹出按应用实时列表（每 2 秒一次，关闭即停止）；菜单栏显示可选「网速」，直接显示上下行速率。
- 流量历史：后台每 60 秒采样一次（可关闭），关掉窗口也记录。分钟总量保留 24 小时，分钟级按应用保留 60 分钟，小时级按应用保留 30 天；可查看 1 分钟、1 小时、24 小时、7 天、30 天。记录写入 Application Support，重启后仍在；没开机或应用没运行的时段留空，不补数。
- TUN 去重：TUN 判定为 utun 上有非链路本地 IPv4，或默认路由走 utun（系统自带的 utun 只有 IPv6 链路地址，不算）。总量只按物理网卡（en*）的 64 位计数器统计；按应用时，把 VPN 转发进程（如鹊桥 LetsVPN）单列为「VPN 转发，已去重」，不计入合计。
- 测速：调用 macOS 自带的 `networkQuality`（Apple 测速服务器），打开页面自动开始，可取消（只结束本应用启动的子进程）。大数字为测速工具的最终结果；曲线为测速期间主网卡每 0.5 秒的实测速率，包含同时段其他应用的流量。延迟分空闲时、下载时、上传时，抖动为空闲延迟相邻差值的平均（样本少于 2 次时显示未知）；带宽档位按实测范围描述用途，不排名。
- 网络卡片：Wi-Fi 信号（RSSI）、链路速率、频段与信道改用 CoreWLAN 读取；Wi-Fi 名称需要定位权限，本版不读取。公网 IP 依次查询 ipify 和 ipw.cn，只接受合法 IP 地址。ChatGPT（chatgpt.com）只要服务器返回任何 HTTP 状态（含 403 人机验证）就算能连上，超时、解析或 TLS 失败写明原因。打开页面时检测一次，5 分钟内不重复。
- 状态页网络卡片改用与流量历史相同的图：最近 30 分钟，每点为 1 分钟平均，没有记录的分钟留空。
- 卸载应用：在「清理预览 › 卸载应用」中选择应用，按 Bundle ID 精确列出应用数据、缓存、偏好设置（含 ByHost）、窗口状态、沙盒容器、网络存储、Cookie、网页数据、日志和登录启动项，显示每项大小，可逐项取消勾选；只有应用名足够具体时才匹配同名目录。共享的 Group Containers 不列入。确认后只移到废纸篓，并记录原位置和废纸篓位置，可一键恢复（原位置已有同名文件时不覆盖）。系统应用、本应用和白名单中的应用不能卸载；目标应用运行时提示用户先自行退出，不强制退出。思路参考 Mole（GPL-3.0），代码为本项目自写。
- 构建：仓库位于 iCloud 同步的「文稿」目录时，文件提供程序会给包目录加 FinderInfo 扩展属性，导致 codesign 拒签；build.sh 在签名前清除扩展属性。

## 验证与边界

新增测试覆盖 nettop 解析、进程增量（新进程、pid 复用、计数归零）、TUN 判定与转发去重、历史聚合/空档/裁剪/写盘重读/30 天清理、满 30 天的记录文件大小、测速结果与失败解析、ChatGPT 可达性分类、公网 IP 校验、卸载清单（相似 Bundle ID、Group Containers、白名单）、运行中拒绝、进废纸篓、记录与恢复。卸载测试只在临时目录中进行，并使用模拟的废纸篓。

息屏不断网：自动核对了开启后系统中出现「阻止空闲睡眠」断言、熄屏期间外接屏断开不撤销、亮屏确认拔屏或拔电后撤销、关闭后完全释放，并确认全程 `pmset -g custom` 没有变化（本功能只用断言，不改睡眠设置）。测试没有触发熄屏或睡眠；真实熄屏 + VPN 场景需要在实机上手动验证。

当前限制：两次采样之间启动并退出的短命进程、以及退出前最后一段的字节无法计入按应用统计（总量不受影响）；系统代理（非 TUN）模式下应用流量经本机代理转发，会算在代理进程名下；转发进程识别依赖已知 VPN 名称或字节特征，不认识的 VPN 可能识别不出；崩溃时最多丢失最近 10 分钟的历史；测速依赖 Apple 测速服务器可达，失败时如实显示错误；卸载不处理需要管理员权限的文件（会保留并提示），清空废纸篓后无法恢复。

本轮未改充电助手或 DNS 助手代码。
