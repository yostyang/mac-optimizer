# 2.9.2 本机验证

日期：2026-11-08

状态：已发布，并完成 GitHub 下载资产回核。

Release：[v2.9.2](https://github.com/yostyang/mac-optimizer/releases/tag/v2.9.2)

## 问题

助手只监视自己的可执行文件被替换或删除。用户把整个旧 App 拖进废纸篓、再拖入新版时，旧助手的文件只是跟着旧包移动，没有被替换，于是旧助手继续运行，主程序却已经是新版。2.9.1 用户实际遇到过这种情况。

## 改动（B08）

| 项目 | 改动 |
|---|---|
| 判断新旧 | `V292.swift` 的 `HelperCheck.judge`：助手进程启动时间（`sysctl KERN_PROC_ALL`，进程名截断为 `MacOptimizerChar`）早于包内助手文件的 ctime 2 秒以上，判为旧版。拷贝会保留 mtime，但 ctime 无法保留，所以用 ctime。 |
| 自动切换 | `HelperCheck.run`：先等最多 12 秒，让原地升级的旧助手自己退出、由 launchd 拉起新版；仍是旧版或没有运行，就注销再注册，最多两轮。注册后需要授权时停下提示，不反复注册。 |
| 不需要重新授权 | 只改主程序，助手代码与签名不变，`helper-cache` 保持 cdhash 稳定。 |
| 设置保留 | 设置本来就存在 `/Library/Application Support`，新助手启动后自动读取。另外在主程序里备份上次确认过的设置（`chargeSettingsBackup`），只有「助手是默认设置、备份不是默认」时补写一次；扩展坞保护标记不从备份恢复；主动卸载助手时清除备份。 |
| 界面 | 充电控制卡显示「已切换到新版充电助手 · 原来的充电设置已保留」；失败时给出原因、重试和「登录项与扩展」入口；需要授权时说明这是升级后的新版、设置会保留。 |

## 自动化结果

- 自检 **681/0**，UI **159/0**，截图 **138/0**（`install-local.sh` 在用户机器上运行）。
- 新增测试 `V292Tests.swift`：新旧判断与时间容差、8 种升级场景（本来就是新版、拖拽替换、原地升级自行重启、需要授权、助手没有运行、两轮仍失败、未安装或等待授权、新版不响应）、设置备份与补写条件、本机只读读数，以及充电卡三种提示。

## 真机验证

| 路径 | 结果 |
|---|---|
| 原地升级（`install-local.sh` 覆盖 `/Applications`） | 旧助手自行退出、新版自动起来，主程序判定为「本来就是新版」，不重复注册；终端显示「充电助手已随新版本重启」「已恢复：常亮=1 接显示器模式=1」；没有授权提示。 |
| 拖拽替换（旧 App 移进废纸篓，再放入新版） | 放入新版后旧助手 89509 仍在运行（复现问题）；打开新版后自动切换到新进程 99648，助手响应正常；充电控制卡显示「已切换到新版充电助手 · 原来的充电设置已保留」；没有授权提示。 |

## 设置保留

第一次原地升级到 2.9.2 后「启用充电上限」为关闭，用户确认升级前本来就是关闭的，设置没有丢失。
