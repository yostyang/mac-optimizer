# 2.2：补完与可信

2.1 的异常提醒没有接入运行中的采样，部分操作发出请求后就显示成功，清理部分失败会丢失待重试项。2.2 将这些实际流程接通，并收起尚未实现的功能入口。

## 本轮行为

- CPU 持续占用、磁盘空间、电池健康异常经过运行中的采样回调判断；提醒默认关闭，开启后关闭窗口和菜单栏仍保留低频监测。
- 提醒页显示通知权限，未允许时保留应用内提示；通知点击可进入相关页面。提醒冷却记录和已知电池健康保存在本机。
- DNS 恢复等待助手回复并读取状态核对。失败、超时或状态不符保留待恢复记录；操作前的迟到刷新及迟到回复不能覆盖新结果。
- 清理在后台逐项移动；失败项保留错误和选中状态，支持重试；移动前再次检查保护路径与白名单，成功记录保留废纸篓目标。
- 进程操作核对目标是否退出；批量操作先确认并逐项核验，未确认完成不计入成功统计。
- 收起自动整理和卸载占位入口。“清理预览”“联网应用与速率历史”等名称与实际能力一致。
- 接电未充电、充满、接电放电、电池供电分别显示；概览以系统内存压力为主，不再把两个算法都称为可用内存。

## 验证方式

`./test.sh` 执行通用构建、自检、界面操作和截图检查。新增测试不仅调用纯函数，也检查 App 的实际采样回调、通知开关与后台调度、模拟助手异步回复、真实临时文件部分移动失败后的重试，以及本测试启动的子进程退出。

额外生成停充电池页的浅色与深色截图；人工查看清理、提醒、供电状态和概览等变更页面。签名和助手二进制须与预期相符，候选包内版本为 2.2（18）。具体结果见随候选包交付的测试摘要。

## 范围边界

本轮不包含完整应用卸载、按应用字节流量、外接显示器助手检测重写、真实逐秒测速曲线。异常到提醒服务的链路用模拟样本检查；不会为测试替用户开启系统通知权限。系统横幅是否展示还受本机通知授权和专注模式影响。插拔电源等物理行为仍需在具体机器上验收。
